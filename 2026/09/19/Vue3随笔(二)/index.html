Vue3 随笔（二）：响应式那点反直觉的地方

发表于2026-09-19|更新于2026-11-18|前端开发随笔
|浏览量:

ref、reactive、toRefs、shallowRef——API 都会背，真正翻车的是这几种情况。

一、ref 在模板里不用 .value，在 script 里必须写

坑在「传出去」的时候：someFn(count) 传的是 ref 对象，不是数字。想传值就写 count.value。

二、reactive 解构会丢响应，这是最常见的 bug

想让解构保持响应，一律 toRefs。或者干脆全程 ref，团队里统一一种写法比什么都对更重要。

三、整体替换对象会让 reactive 断链

要么用 ref：

要么逐字段赋值。判断口诀：这个对象会被整体替换吗？会就用 ref。

四、大对象别用 ref 全程深度监听

一个上万条数据的表格，每次改一个字段都深度遍历，卡得莫名其妙。

shallowRef 的语义是「我只关心引用变没变」。配合 triggerRef(rows) 手动触发也行。

五、watch 和 watchEffect 分工

用途 注意
watch 明确知道要监听谁 默认浅比较，对象内部变化要 deep: true
watchEffect 依赖自动收集 会跑两次（初始化 + 依赖变化），慎用于请求

多个请求同时飞回来写同一个变量，是「数据乱跳」的头号原因，AbortController 是最省事的解法。

六、computed 别写副作用

七、props 改不了，别想着「先改再同步」

父组件是数据的唯一来源，子组件存草稿。

小结清单

  • script 里 ref 记得 .value，模板里不用
  • reactive 解构必 toRefs
  • 对象会被整体替换 → 用 ref
  • 大数据列表 → shallowRef
  • 请求类副作用配 AbortController 清场
  • computed 只算不写
  • props 只读，编辑用本地草稿
